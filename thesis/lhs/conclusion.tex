\section{Conclusion}

This thesis draws from software design methodologies to develop, structure, and verify cybersecurity models. This research demonstrates the value of modularity and software-inspired techniques for building these models in an interdisciplinary and collaborative fashion. 

CyberVITBridge is part of an ongoing effort to make VITAMIN an integral model-checking component for the cybersecurity modelling process. We showed that with the proper integration with model-checking methodologies, we can provide an iterative, experiential process for creating CyberBattleSim models. Despite being visual-based, reward-mechanism simulation software, the introduction of formal verification into the workflow of using that software provides unique benefits for practitioners of CyberBattleSim. One major shortcoming is the computational complexity of generating the full attack path in CyberVITBridge. We roughly determined bounds for the CyberBattleSim model to be able to compile to a usable format in VITAMIN, specifically based on the number of vulnerabilities introduced in the model. Further optimization of our implementation would prevent this restriction to toy models. 

In terms of ease-of-use, CyberVITBridge is solely in a Python environment, making it relatively inaccessible to web-based VITAMIN users. An API implementation of the CyberVITBridge export functionality should alleviate a window-switching issue, hopefully paving the way for an appropriate UI or web-based VITAMIN extension to make bridge instantiation easier. Eventually, users of CyberBattleSim shouldn't have to exit the experimentation platform at all, but rather treat the VITAMIN model-checker as an external resource to acquire in a Jupyter cell before starting another simulation.

The failure of compositionality and reusability in the CyberVITBridge modelling methodology also impedes the applicability of this workflow beyond a particular few kinds of cybersecurity models, in the context of CyberBattleSim. A more general class of cybersecurity models based on game theory already contained natural shared structure. By recognizing the relationships between state-of-the-art game-theoretic models in cybersecurity, compositional game theory was a suitable candidate for expressing these relationships. Modularity provided through compositional game theory gives clear advantages for conceptually adapting or composing models together. The \textit{open-games-hs} engine and the DSL provides a new modelling environment, under a models-as-code paradigm. The addition of a structured development process makes these advantages readily available for practitioners. As an "applied-applied" category theory project, we showed that using the category of open games and its Haskell implementation can serve effectively as a backend for a platform that allows cybersecurity modellers to experiment, collaborate, and save their models. The introduction of design patterns to compartmentalize certain operations makes \textit{open-games-hs} more accessible and straightforward-to-use. These are organized into four \textbf{modules}, which address how to keep constructed models compatible and self-documenting. These patterns reflected a clear boundary between the construction and analysis of the games. Most notably, \textbf{Module 3} can be developed independent of the structure of a game, and \textbf{Module 2} can ``fit'' into any user-defined compatible parameterizations as provided by \textbf{Module 1}. Then, \textbf{Module 4} is used in establishing an iterative, test-driven process to continuously update the resultant models then leverages these design patterns to organize a repository of models. This test-driven process specifies both unit and functional tests, and expedites the testing of different modules independent of each other. 

However, working with \textit{open-games-hs} and the DSL still comes with a steep learning curve, and a dependence on a Haskell working environment. While the design patterns ultimately streamline this workflow, the future adoption of this tool for cybersecurity research could be hindered by lack of widespread use within the simulation or modelling research community. Furthermore, if \textit{open-games-hs} is relatively self-contained since it provides both model creation and equilibrium analysis capabilities together, several refinements or optimizations must still be made to properly compare with cybersecurity models created in the traditional sense. Citing examples from \cite{Collins2025}, evolutionary games, differential games, and Gestalt multistage games currently cannot be modeled using compositional game theory. Efforts towards extending compositional game theory to formalize other solution concepts and game structures, like most recently for extensive form games (\cite{hedges2017morphismsopengames} and \cite{capucci2021translating}), can be followed with an implementation in \textit{open-games-hs} to accommodate these other security game types. 

In terms of evaluating our proposed methodologies, the immediate next direction for both CyberVITBridge and the open games design patterns is to conduct behavioral and qualitative studies with modellers to evaluate how well these methodologies perform in future studies. Analysis of interdisciplinary modelling through the lens of psychological and sociological considerations and group performance, like in \cite{nikolicFacilitatingInterdisciplinaryModelling2007} and \cite{rossiniFrameworksIntegratingInterdisciplinary1979}. An analysis of the open-games models presented in this thesis could also be evaluated within the "triangle framework" \cite{caulfieldMetamodellingEcosystemsSecurity2022}. We precisely hope that the game-theoretic models developed (possibly compiled as string-diagrams) or future integration with other simulation software would provide a greater degree of "executability" "conceptuality," when other game-theoretic models have been evaluated to be weaker in these qualities.
